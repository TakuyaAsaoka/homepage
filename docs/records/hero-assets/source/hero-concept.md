# Homeヒーロー演出 — 構想書

最終更新: 2026-08-07（第2版）

> このドキュメントは方針が変わるたびに更新する。Issue化のタイミングで `docs/records/specs/` へ移す。

---

## 1. 目的

Homeのファーストビューに演出を作る。サイトの目的の優先順位は **名刺代わり ＞ 依頼獲得 ＞ 発信ハブ**。
施主の言葉として「**ここは圧倒的なクオリティを出したい場所**」「妥協しない」。

## 2. 表現の構想

```
【第1幕】文字が散らばっている → 集まる → 松のASCIIアートになる
【転換】  ASCIIから日本画へ
【第2幕】絵の中で無限ループ
```

### なぜこの表現か

| 要素 | 意味 |
|---|---|
| 文字が集まる | **エンジニアである**ことの表現。コードが積み上がって作品になる比喩 |
| 松 | 施主が個人的に好きなモチーフ。日本風の松の絵 |
| 絵になる | 素材（文字）が完成品（作品）になる物語 |

### 第1幕：文字の出自（検討中）

当初は「松を構成する文字だけが散らばる」で確定していたが、以下の案が追加された。

- **名前**（`ASAOKA Takuya`）が読める状態から始まり、ばらけて松になる
- **プログラムコードの断片**から始まる

「名前が松になる」は名刺代わりのサイトとして意味が強い。
技術的注意: 松の濃淡は `# % * + : ; , .` の文字の重さで表現しているため、名前の文字のままでは階調が崩れる。**散らばっている間は名前/コード、集まる途中で松の文字に変化する**構成になる。

### 第2幕：何が動くか

| 要素 | 動く | 理由 |
|---|---|---|
| **霞** | **必須** | 「目立たないが後ろで動くと**奥行き感**が出て、**作り込まれている印象**になる」 |
| 舞い落ちる紅葉 | 必須 | 動きの主役 |
| 松の枝葉 | あれば良い | 「動かなくてもいい」と判断済み |
| 松の幹・岩・灯篭 | 静止 | — |

### 不採用

- 季節連動（春夏秋冬で色が変わる）
- 鶴・月
- 小枝（ASCIIで「認識しづらい」ため本数0で確定）

## 3. 確定していること

### 第1幕：ASCII松

プロシージャル生成。形状は正規化座標の純関数で**密度非依存**。

| 分類 | 値 |
|---|---|
| 密度 | 150×56 |
| 色 | 彩色ON・鮮やかさ100・くっきり100 |
| 濃淡 | コントラスト200・全体の濃さ150・樹皮121・苔8 |
| 幹 | 傾き50°・太さ100・長さ100・中腹の枝116・線の揺らぎ110 |
| 樹冠 | 大きさ109・もこもこ102・葉の詰まり100 |
| 根 | 張り出し110・太さ38・沈み込み100 |
| 小枝 | **本数0（不採用）** |

※ 絵の松に合わせて左右反転・位置調整が必要（絵が確定したので今後合わせる）

### 第2幕：絵

AI生成（ChatGPT画像生成）した1枚絵。和紙地・琳派風。松・紅葉・石灯篭・ツツジ・霞・散る紅葉がすべて調和して含まれている。**1672×941**。

### 技術

- **Astro v6 / 静的サイト / GitHub Pages / ランタイム依存ゼロ**（既存の設計思想）
- **GPU無効環境の訪問者が現実に存在する**（開発者のChromeが該当。Safariでは60fps）

### 配信方式：全部を動画にする（2026-08-07 決定）

ブラウザ側は `<video>` の差し替えだけにする。**転換の実装が不要**になり、GPU無効環境でも確実に動く。

```
導入.mp4   [文字が集まる → ASCII松 → 絵に変わる]   1回だけ再生
    ↓ ended イベントで差し替え
ループ.mp4 [絵の中で霞と紅葉が動く]                無限ループ
```

| 動画 | 作り方 | 費用 |
|---|---|---|
| 導入（横） | **Canvasで再生して録画** | **$0** |
| ループ（横） | AI生成（Seedance 2.0） | 約$3 |
| 導入（縦） | Canvasを縦構図で録画 | **$0** |
| ループ（縦） | AI生成 | 約$3 |

- 第1幕はCanvasで作るのは変わらない。**それを録画して動画にする**
- ASCIIは密度非依存なので、縦構図は**パラメータを変えて録画するだけ**
- ファイルを2本に分けるのは、**モバイルでループ動画だけを読めば通信量が半分**になるため
- モバイルでも**フル演出を見せられる**（縦用を用意すればよい）

**却下した案**: Canvas（第1幕）＋動画（第2幕）のハイブリッド。
唯一の優位点は「画面幅に無段階で追従できる」ことだが、実際は縦・横の2パターンで足りる。
それに対して転換の実装コストとGPU無効環境での描画負荷が残るため見送り。

## 6. 技術選定の変遷（なぜ今の形になったか）

| 案 | 結果 | 原因 |
|---|---|---|
| 絵もプログラムで描く | ❌ 3回作り込んで「子供の落書き」 | 形状関数の情報量が絵の上限になる。日本画の質は数式で再現できない |
| AI生成の部品を合成 | ❌ 調和しない | 素材ごとに空気感が一体で描かれ、切り出すと矩形の名残が出る |
| 1枚絵＋Canvasで霞を重ねる | ❌ 「動きが不自然・画質が低い」 | 絵の中身が静止したまま重ねた要素だけ動くのでレイヤーが分離して見える |
| **1枚絵を動画化** | **← 現在** | 失敗の共通原因は「日本画の空気感をブラウザ内で合成しようとした」こと。合成をやめて完成品を配信する |

### 却下した技術

| 技術 | 却下理由 |
|---|---|
| Three.js / PixiJS | セル数が数千規模でWebGLの損益分岐点（数万）に届かない |
| GSAP | 各セルは共有進捗tの純関数で書けるためトゥイーンエンジン不要 |
| シェーダー | 疎密度では1文字が大きく、ピクセル単位のにじみは文字の輪郭を溶かして主題を弱める |
| 深度マップ＋パララックス | 「カメラが動く」演出であって「絵の中身が生きる」演出ではない。WebGL必須 |
| AI自動レイヤー分離（SAM） | 物体の境界で切るだけ。空気感が要素をまたぐ問題は解決しない |
| DOM/CSS transform 合成 | GPU無効環境でCanvasと同等に遅い（実測）。レイヤー数が増えると逆効果 |

### サービス選定

| サービス | 判定 |
|---|---|
| **Seedance 2.0**（現在使用） | スタイル維持がGen-4.5より優れる。モーション安定性76.0 vs 43.0。**first/last frame指定でループが作れる** |
| Runway Gen-4.5 | 権利は最もクリーンだが、**Gen-3廃止でキーフレーム制御ができない**（ループ不可） |
| Luma Dream Machine | Loop機能・16キーフレーム。ただし**無料枠なし**（Plus $30/月） |
| Kling | **✕ 「Kling AIによって生成された」の表示義務**、学習・広告への無償ライセンス、中国法域 |
| ChatGPT（Sora） | **✕ 2026年4月にChatGPT内の動画生成が終了** |

### 素材処理（コード化済み）

1. 白背景で生成（明度250以上）
2. 明度→アルファ変換＋**アンマルチプライ**（白フチ防止）
3. 外接矩形でトリミング
4. 霞は端フェード＋帯の自動分離

## 7. 実装方針（Fableのレビューを反映）

### フォールバック（2段）

```
prefers-reduced-motion? ─ yes → 静止画（第1幕もスキップ）
        │no
sessionStorage に判定あり? ─ static → 静止画
        │no
第1幕を再生（＝これが計測窓）→ 33ms超フレームの割合で判定
        ├ 合格 → 第2幕（無限ループ）
        └ 不合格 → 転換のフェード先を静止画にすり替える
```

- 指標は平均fpsではなく**ロングフレーム率**（平均はGCスパイクに鈍感）
- 切替は**転換点で1回だけ・単方向**（再生中の動的切替はちらつきの元）
- **静止画は1枚で3役**（reduced-motion / 低性能 / JS無効の`<noscript>`）
- `IntersectionObserver` でヒーローが画面外に出たらrAF停止
- タブ復帰時のdeltaクランプ（進捗が跳ぶのを防ぐ）

### ファイル構成（全部動画にしたため簡素化）

```
src/components/PineHero.astro   マークアップ＋CSS（video 2本・poster・見出し）
src/scripts/pine-hero.ts        導入→ループの差し替え、画面幅による出し分け、フォールバック
```

第1幕をCanvasで描く実装は**動画の書き出し用**として別途保持する（本番のランタイムには載らない）。

- 素材は `src/assets/hero/` に置き ESM import（ハッシュ付きファイル名・`base`解決）
- Astro `<Image>` は使わない（drawImageの入力なので最適化パイプライン不要）
- 手元でWebP化してコミット。**合計300KB以下を目標**
- 高さは `svh`（モバイルのアドレスバー伸縮で再レイアウトしないため）

### 実装順序（安全網から作る）

1. 静止画（poster）＋ `prefers-reduced-motion` — **最終フォールバックを先に完成**させる
2. ループ動画を `<video autoplay muted loop playsinline>` で配置 → 実機検証
3. 導入動画を作る（Canvas録画 → エンコード）→ ended で差し替える実装
4. 縦用（モバイル）の出し分け
5. 総合検証（GPU無効Chrome・iPhone実機・低電力モード・dark・回転・ClientRouter）

「安全網から作る」ため、どの時点でもマージ可能な状態を保つ。
