# 制作の画像を astro:assets に載せる 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 制作詳細ページの `<img>` に画像の実寸（`width` / `height`）を出力し、画像の読み込み完了時に本文が下へずれるのをなくす。

**Architecture:** 画像の置き場所を `public/images/`（Astroが中身を読まない）から `src/content/works/images/`（Astroが読む）へ移す。Content Collections の `image()` ヘルパーでスキーマを定義すると、フロントマターの文字列が寸法つきの画像として読み込まれ、`<Image>` コンポーネントが寸法を属性に出す。CMS（Sveltia）には制作コレクション専用の保存先を設定し、Markdownからの相対パスで保存させる。

**Tech Stack:** Astro v6（astro:assets / Content Collections）、Sveltia CMS、TypeScript（strict）

- 設計: [`docs/records/specs/2026-08-10-133-astro-assets-design.md`](../specs/2026-08-10-133-astro-assets-design.md)
- Issue: #133

## Global Constraints

- 品質ゲート: `npm run build && npm run check && npm run test:run` を warning 0件で全パスさせる
- コードコメント・コミットメッセージは日本語
- 自動テストは追加しない。この変更で増えるのはAstroコンポーネントの出力とコンテンツスキーマであり、Vitest（`environment: "node"`）で検証できる純ロジックが増えないため。検証はビルド生成物（`dist/`）の中身を確認する形で行う
- `image()` を使う際は `defineCollection` の `schema` を関数形式（`schema: ({ image }) => z.object({...})`）にする必要がある
- `BaseLayout` / `BaseHead` / `StructuredData` の `image?: string`（画像のURL）は変更しない

### Task 1: 制作の画像を astro:assets に載せる

制作の `image` を `image()` ヘルパーで受け、詳細ページを `<Image>` に置き換える。この時点で Issue の主目的（実寸の出力）が達成される。

**Files:**
- Modify: `public/admin/config.yml:48-52`（works コレクションの定義）
- Modify: `src/content.config.ts:5-23`（works のスキーマ）
- Modify: `src/pages/works/[...slug].astro:1-45`
- Modify: `src/components/WorkCard.astro:1-23`
- Modify: `src/components/StructuredData.astro:64`（コメントのみ）

**Interfaces:**
- Produces: `work.data.image` の型が `string | undefined` から `ImageMetadata | undefined` に変わる。`ImageMetadata` は `{ src: string; width: number; height: number; format: string }`。Astro のグローバル型なので import は不要
- Produces: `WorkCard` の Props `image?: ImageMetadata`
- Consumes: なし

- [ ] **Step 1: CMS の保存先を制作コレクションに設定する**

`public/admin/config.yml` の works コレクション、`slug: "{{slug}}"` の次の行に追加する（`fields:` の前）。

```yaml
    # 画像は制作と同じ場所（src/content/works/images/）に置き、Markdownからの相対パスで保存する。
    # public/ に置くとAstroが中身を読めず、img に寸法を出せない（読み込み時に本文がずれる）。
    # public_folder は先頭が "." のときだけそのまま使われ、それ以外は "/" を前置される
    media_folder: "images"
    public_folder: "./images"
```

- [ ] **Step 2: スキーマを image() ヘルパーに変える**

`src/content.config.ts` の `works` を次の内容に置き換える。`schema` が関数形式になる点と、インデントが1段深くなる点に注意する。

```ts
const works = defineCollection({
  loader: glob({ pattern: "**/*.md", base: "./src/content/works" }),
  schema: ({ image }) =>
    z.object({
      title: z.string(),
      description: z.string(),
      tags: z.array(z.string()).default([]),
      // image() はMarkdownからの相対パスを解決し、寸法つきの画像として読み込む。
      // CMSで一度設定した画像を消すと空文字が残るが、image() は空文字も「画像あり」として
      // 通してしまうため、先に空文字を受けてから「未設定」に正規化する
      image: z
        .union([z.literal(""), image()])
        .optional()
        .transform((v) => v || undefined),
      url: z.url().optional(),
      // 公開日は暦日（どこで見ても動かない日付）。瞬間として持つとビルド環境のTZで1日ずれるため、
      // "YYYY-MM-DD" 文字列に正規化して保持する
      pubDate: z.coerce.date().transform((d) => d.toISOString().slice(0, 10)),
      draft: z.boolean().default(false),
    }),
});
```

`z.union([z.literal(""), image()])` の順序は変えないこと。`image()` は空文字を「画像あり」として通してしまうため、先に `z.literal("")` で受ける必要がある。

- [ ] **Step 3: 詳細ページを `<Image>` に置き換える**

`src/pages/works/[...slug].astro` のフロントマター1行目（`---` の直後）に import を足す。

```astro

```

`BaseLayout` に渡す2箇所を `.src` にする。

```astro

```

```astro

    datePublished: work.data.pubDate,
    keywords: work.data.tags,
    image: work.data.image?.src,
  }}
```

`<img class="hero-image" ...>` のブロックを、コメントごと次に置き換える。

```astro
    {/* 詳細ページは実際の画像があるときだけ出す（デフォルト画像は制作の内容を表さないため）。
        Image は寸法を属性に出すため、読み込み前から高さが確保され本文が押し出されない。
        ページ最上部に出る画像なので、既定の遅延読み込み（loading="lazy"）は打ち消す */}
    {work.data.image && (
      <Image
        class="hero-image"
        src={work.data.image}
        alt={work.data.title}
        loading="eager"
        decoding="async"
      />
    )}
```

`<style>` の `.hero-image` は変更しない。`src/styles/global.css:139-142` の `img { max-width: 100%; height: auto }` があるため、`width` / `height` 属性が付いても縮小時に縦横比は崩れない。

### Task 2: デフォルト画像も astro:assets に載せる

OGPと一覧カードのデフォルト画像（`og.png`）を `src/assets/` に移し、一覧カードを `<Image>` に置き換える。これで `public/images/` に画像が無くなり、カードのサムネイルもWebPで配信される。

**Files:**
- Rename: `public/images/og.png` → `src/assets/og.png`
- Modify: `src/consts.ts:12-13`
- Modify: `src/components/BaseHead.astro:3,23`
- Modify: `src/components/WorkCard.astro:1-23`

**Interfaces:**
- Consumes: Task 1 で定義した `WorkCard` の Props `image?: ImageMetadata`
- Produces: `src/consts.ts` の `DEFAULT_IMAGE`（型は `ImageMetadata`）。旧 `DEFAULT_OG_IMAGE`（`string`）は削除する

- [ ] **Step 1: og.png を src/assets へ移す**

```bash
mkdir -p src/assets && git mv public/images/og.png src/assets/og.png
```

`public/images/.gitkeep` は残す。`public/admin/config.yml` のグローバル `media_folder: "public/images"` が指す先なので、フォルダごと消さない。

- [ ] **Step 2: consts.ts を import に変える**

`src/consts.ts` の末尾2行を置き換える。

置き換え前:

```ts
// OGP（SNS/チャット共有）のデフォルト画像。ページ個別指定が無いときのフォールバック
export const DEFAULT_OG_IMAGE = `${BASE_PATH}images/og.png`;
```

置き換え後:

```ts
// OGP共有と一覧カードのデフォルト画像。ページ個別指定が無いときのフォールバック。
// import で持つことで寸法が分かり、ファイルを消せばビルドが失敗する（URL直書きだと公開後まで気づけない）
export { default as DEFAULT_IMAGE } from "./assets/og.png";
```

- [ ] **Step 3: BaseHead を新しい定数に合わせる**

`src/components/BaseHead.astro` の import 行と `resolvedImage` を変える。

```astro
import { SITE_LOCALE, BASE_PATH, DEFAULT_IMAGE } from "../consts";
```

```astro
const resolvedImage = image ?? DEFAULT_IMAGE.src;
```

`og:image` には元画像（PNG）のURLが入る。`<Image>` が生成するWebPではなく元画像を使うのは、SNS側の対応形式を考えると安全なため。

- [ ] **Step 4: WorkCard を `<Image>` に置き換える**

`src/components/WorkCard.astro` のフロントマター1行目に import を足す。

```astro
import { Image } from "astro:assets";
```

import 行と `thumbnail` を変える。

```astro
import { BASE_PATH, DEFAULT_IMAGE } from "../consts";
```

```astro
// 画像なしの制作でもカードの見た目を揃えるため、未設定時はデフォルト画像で埋める
const thumbnail = image ?? DEFAULT_IMAGE;
```

`<img class="thumbnail" ...>` を `<Image>` に置き換える。

```astro
  <Image class="thumbnail" src={thumbnail} alt="" loading="lazy" decoding="async" />
```

幅は指定しない。カードの表示幅は2カラム時で約350px、1カラム時で約736pxと幅があり、固定幅を決めると片方で粗くなるため。枠は `<style>` の `aspect-ratio: 16 / 9` が確保しているので、属性の寸法は表示に影響しない。`<style>` は変更しない。
